# 路径规划仿真预览

只保留一种检测逻辑：**预接近终点保持 tool0 +Z 与拍照时同向，允许绕自身 Z 轴选角度**。
前面的 MoveIt/OMPL 绕障运动不持续锁姿态；到预接近点后，固定选定的完整朝向，
沿工具 +Z 直线接近名义接触点，再沿原直线撤离、返回拍照关节原位。

不再保留自由朝向、完整拍照朝向对照、全检测段直线、局部倾斜、就近数值 IK、
150°/180°运动筛选或单步求解时间试验。碰撞、地面、关节范围和实际端点检查继续保留。
这次清理不改变相机、TCP 通信或真机限力/导纳控制方式。

## 启动

所有命令在 `ros_ws` 下执行：

```bash
source /opt/ros/jazzy/setup.bash
colcon build --packages-select robot_task_control --executor sequential
source install/setup.bash
ros2 launch robot_task_control path_preview.launch.py
```

无需额外选择模式；旧的显式 `detection_orientation_mode:=axis_only` 仍可使用。
其他模式已删除，不再提供可切换入口。只计算、不打开 RViz：增加 `rviz:=false`。
修改源码 YAML 后可直接读取它，避免默认安装目录的旧配置未更新：

```bash
ros2 launch robot_task_control path_preview.launch.py config_file:="$PWD/src/robot_task_control/simulation/path_preview.yaml"
```

配置不会热更新，修改后须关闭旧预览再启动；终端和 JSON 会记录实际配置文件。

## 点位与动作

默认流程及中间点文件为 `config/diagnostics/arrival_detect.yaml`。
仿真配置 `path_preview.yaml` 的 `photo_pose` 只覆盖内存中的拍照位：
基座下 tool0 XYZ `(0.240,0.390,0.580) m`、RPY `(-180,0,-90)°`；不修改真机流程文件。
删除该覆盖字段即可使用流程文件自身的拍照位。
相机检测坐标可直接改顶层 `camera_points_mm: [0.0, 0.0, 50.0]`，单位毫米；
多点为 `[x1,y1,z1,x2,y2,z2]`。这是相机系下的探针接触目标，不是相机安装TF或拍照位。
该字段优先于工作流/主配置；删除后才继承。它只影响仿真，不会同步改真机或远端TCP坐标。
顶层 `approach_clearance: 0.05` 单独设置仿真预接近距离，单位米（允许大于0、最多0.2米）。
例如改为 `0.02` 就在名义接触点后退2 cm作为预接近点；名义接触坐标不变。
删除该字段才继承主配置，修改它不会改真机；终端和报告会记录实际使用的距离。

`waypoint_poses` 是完整的仿真笛卡尔中间点清单，位置单位米，RPY 为度：

| 点位 | 基座下 tool0 XYZ（mm） | RPY（度） |
|---|---|---|
| 中间点一 | (-435,254,720) | (-90,0,45) |
| 中间点二 | (110,450,600) | (180,0,-25) |
| 拍照位 | (240,390,580) | (-180,0,-90) |

去程按一→二→拍照，回程按拍照→二→一，两个方向使用相同的中间点位姿。
可复制任一中间点块新增 `to_camera_extra`（名称必须 `to_` 开头且唯一），
按 YAML 书写顺序执行，返回自动倒序生成，无需再写回程点。
删除一个块即移除该中间点；`waypoint_poses: {}` 表示不经过笛卡尔中间点；
删除整个字段则继承原工作流中间点。此项不移除关节过渡位或拍照位。

```yaml
camera_points_mm: [0.0, 0.0, 50.0]
waypoint_poses:
  to_camera_via:
    position: [-0.435, 0.254, 0.720]
    orientation: [-90.0, 0.0, 45.0]
  to_camera_intermediate:
    position: [0.110, 0.450, 0.600]
    orientation: [180.0, 0.0, -25.0]
```

当前相机点 `[0,0,50] mm` 的实测预览在预接近段失败，尚未验证接触/撤离和完整回程。
下面的14段成功记录是此前测试点的历史结果，不代表改点后仍可通过。
另有仿真关节过渡位2 `transition2_joint_degrees: [-45,-90,180,0,0,90]`，单位度，
关节顺序为基座、肩、肘、腕1、腕2、腕3。去程插在原过渡位之后，回程插在原过渡位之前。
角度不取模、不裁剪。按要求，当前仅在该仿真 launch 生成的内存 URDF 中，把肘部硬/软限位都设为±250°，
使实际规划范围确实是±250°而不是再扣8.59°。MoveIt、模型TF与RViz使用同一个修改后的仿真模型。
共享真机 URDF/Xacro、其他关节的安全余量以及碰撞检查均不改；这是假设的仿真范围，不代表硬件允许范围。
原共享模型肘部硬限位±180°，0.15 rad安全余量后的软限位约±171.41°。
此前实测 MoveIt 会把180°目标压到171.41°并返回SUCCESS，因此仿真继续另行核验实际规划关节终点：
超过原关节目标容差0.005 rad就报失败，不将修改后的关节目标加入成功动画；不自动降低用户请求角度。
仅仿真肘范围改为±250°后，使用当前源码点位实测一次，14段完整往返均为PLANNED，
接近及撤离笛卡尔比例均为1.0；过渡位2去程肘角约179.73°、回程约179.84°，均在原0.005 rad容差内。
这个结果只证明修改后的仿真模型本轮规划通过，不能当作原模型或真机允许±250°的证明。
此前中间点一(-240,400,600)、中间点二(110,450,600)重复测试两轮，均未通过过渡位→中间点一：第一轮输出轨迹被最终碰撞校验拒绝，
碰撞对为 `forearm_accessory_link` 与 `terminal_assembly_link`；第二轮 15 秒内未找到路径。
因此不能把本组点位标记为完整往返通过，后面的中间点二、拍照和检测段没有在这两轮中实际通过。
此前旧中间点＋新拍照位测试：默认完整预览在中间点二→拍照位的位姿目标规划中失败；
独立 IK 检查找到无碰撞终点，以该关节终点作路径诊断可通过。
从该已验证拍照构型单独测试，预接近、名义接触、撤离、回拍照位四段均通过，接近/撤离完成比例均为 1.0。
该检测段诊断不等于默认完整流程通过，也没有把固定关节解或额外选解策略写入默认流程。
关节角和 RPY 单位为度，XYZ 为米；相机检测点单位为毫米。

1. 行车位 → 过渡位1 → 过渡位2 → 中间点一 → 中间点二 → 拍照位。
2. 拍照位冻结相机和探针变换；相机点变成基座下的探针尖端接触目标。
3. 沿拍照工具 +Z 的反方向退 **5 cm**，得到探针尖端预接近点。
4. 使用真实安装偏移补偿 tool0 目标；直接向 MoveIt 提交尖端位置与终点工具 Z 方向约束。
   允许绕自身 Z 连续选角，不添加整个绕障过程的姿态路径约束。
5. 通过实际 FK 确认预接近尖端位置和工具轴；冻结到达时选定的完整工具朝向。
6. 沿实际工具 +Z 笛卡尔直线到名义接触点，再沿原直线退回预接近点。
7. 回拍照关节原位，然后中间点二 → 中间点一 → 过渡位2 → 过渡位1 → 行车位。

相机 +Z 与工具 +Z 同向时，相机接触点 `(1,2,13) cm` 对应预接近点 `(1,2,8) cm`。
这个点是探针尖端目标，不是 tool0 原点；tool0 位置始终补偿 `tool0→probe` 安装偏移。
工具 Z 不等于基座 Z；沿工具 Z 的位移用基座坐标表示时，X/Y 可能变化。

回程复用去程中间点的位置和朝向，每段重新规划并检查碰撞，不直接反放整条去程轨迹。
要使用另一份点位文件：

```bash
ros2 launch robot_task_control path_preview.launch.py workflow_file:=/绝对路径/点位.yaml
```

## 约束、安全与显示

- 使用现有 LS65 URDF/SRDF、完整末端及侧装盒碰撞模型、Z=0.08 m 地面。
- 轴向约束用冻结的拍照工具坐标系 `path_preview_frozen_tool_axis` 表达。
  不是把基座 Z 的旋转自由度误当成绕工具 Z。
- 位置约束带探针相对 tool0 的实际安装偏移，避免选角后尖端漂移。
- 不放宽原位置/轴向容差；真实 FK 复核预接近和接触端点，检查直线方向和横向误差。
- 接近和撤离笛卡尔完成比例必须至少 0.999。预接近、接触、撤离、返回拍照位四段全部通过才加入动画。
- 失败就停止后续规划，不跳过失败段；仅播放此前成功的部分一次，停在最后有效点。
- RViz 使用原生 `Planned Motion - Trajectory Slider`，显示轨迹以 0.1 秒间隔播放一次；
  显示速度不是实际执行速度，不自动循环，不叠加彩线或标签。
- JSON 报告为 `/tmp/robot_task_path_preview.json`，包含分段状态及
  `detection_orientation_trials` 的 `AXIS_ONLY_CONTINUOUS_SPIN`、接触点、工具轴和拒绝原因。
  失败保留 `FAILED/PARTIAL_STOP`，不冒充完整往返成功。

仅启动 MoveIt、模型 TF、虚拟关节状态、地面场景、预览节点和可选 RViz。
固定独立 `ROS_DOMAIN_ID=190 / LOCALHOST`，MoveIt 禁止轨迹执行。
不启动硬件驱动、相机、串口、底盘或轨迹控制器，不模拟接触力、额外探入或漆膜厚度。
不要把域 190 用于真实设备；预览通过也不能代替真机接触验证。

Ctrl+C 或关闭 RViz 窗口退出该组仿真。修改源码后需要重新构建并 source。
其他入口见[统一文档](../README.md)和[真机漆膜检测说明](../tasks/PAINT_DETECTION.md)。
